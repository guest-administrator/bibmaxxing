# Bibmaxxing-Py — Design Spec

**Date:** 2026-04-29
**Author:** Creator (Navy CWT E-7 candidate) + Claude
**Status:** Approved design, awaiting implementation plan
**Target codename:** `bibmaxxing-py`

---

## 1. Context

The existing Bibmaxxing is a vanilla-JS single-page web app (~2774 LoC across 13 modules) for drilling Navy advancement-exam references. It uses IndexedDB for state, SM-2 spaced repetition, Markdown-rendered study guides, and a Bib-interchangeable architecture currently populated with the CWT-E7 Bib (461 flashcards, 63 study guides, 55 embedded images, ~3 MB of doctrine PDFs and books on disk).

This spec defines a **parallel Python rewrite (`bibmaxxing-py`)** intended to **replace the web app as the daily-driver study tool** while sharing the same on-disk content (`data/bibs/<BIB>/`) so edits flow into both apps.

The Python fork's identity is a **tier-C, pure-procedural, game-feel** experience — full-screen reactive shaders, generative procedural art, no curated assets — paired with a **disciplined library mode** for reading the dense Markdown study guides without visual interference.

---

## 2. Goals

1. **Daily-driver replacement** — fast launch, keyboard-first, comfortable for 30+ minute sessions.
2. **Functional parity** with the existing web app: dashboard · flashcards · quiz · mock exam · references · study guides · add question.
3. **Tier-C maximalist visuals** in drilling mode (full-screen aurora, particle field, 3D-tilted card stack, post-processing).
4. **Pure-procedural art** — every visual element generated by code (shaders, particles, geometric primitives). Zero curated image assets except optional bundled fonts.
5. **Library mode** — calm, typography-first reading view for Markdown study guides with toned-down ambient effects; preserves the 55 embedded images already authored.
6. **Shared content** — read the existing `data/bibs/` directly. No content fork. Edits in either app pick up next launch.
7. **Discoverable keybindings** — every key shortcut surfaced via status bar + inline labels + `?` overlay.
8. **Verbose logging** — rotating file logger, configurable level, structured K=V records, crash dumps.
9. **Distributable** — single-file `.exe` via PyInstaller; runs on Win 10/11 boat workstations without admin or Python install.

## 3. Non-goals

- No mascot / animated companion character (room-as-companion only).
- No curated illustrations, sprites, or commissioned art assets.
- No mobile, web, or cloud-sync target.
- No analytics, telemetry, or network calls.
- No new flashcard authoring features beyond what the web app already has.
- No replacement of the web app — both coexist; the user picks per session.

## 4. Architecture & Stack

### 4.1 Stack

| Layer | Choice | Rationale |
|---|---|---|
| Language | Python 3.12+ | Modern type syntax, pattern matching, `dataclass(slots=True)` |
| Window/event/2D | **Pyglet 2.0+** | Mature pure-Python, batched draws, robust text layout, OpenGL-backed |
| Shaders/FBOs | **ModernGL** | Direct GLSL, FBOs, instancing, uniforms — full shader ceiling |
| Persistence | **sqlite3** (stdlib) | Natural Python equivalent of IndexedDB, zero-config |
| Markdown parse | **markdown-it-py** | CommonMark + GFM tables, token stream we render ourselves |
| Code highlighting | **pygments** | Library-mode code blocks |
| Image loading | **pillow** | Inline images in MD, font glyph atlases |
| Audio | `pyglet.media` (built-in) + numpy | Subtle UI cues, **synthesized in code** (no WAV files) to honor pure-procedural rule |
| Dev file watch | **watchdog** | Hot-reload of `.glsl` and `.md` files in dev mode |
| Console color (dev) | **colorama** | Mirrored stderr in `--dev` mode |
| Packaging | **PyInstaller** | Single-file `.exe`, no Python install required on target |

### 4.3 Process model

- Single window, single process.
- Default window: **1280 × 800**, resizable; layout engine responds to resize. Fullscreen toggleable via `F11`.
- **Fixed-timestep update / variable-render** at 60 fps target.
- Event loop: Pyglet pumps OS events → updates state → calls render.
- Render pipeline: 4-pass FBO chain orchestrated in `render/pipeline.py`. FBOs resize on window resize.
- All shader files watched in `--dev` mode; touch a `.glsl` → recompile uniforms live.
- `--low-power` (or auto-detect on integrated GPU) drops post-processing pass and caps particle count to ~150, keeping the app usable on weak boat-workstation hardware.

## 5. Render Pipeline & State Reactivity

### 5.1 Frame loop

```
update_state(dt)                 # lerp mood toward target, decay particles, run tweens
render():
    fbo_aurora.bind()            → fullscreen quad, frag shader (time, mood, intensity, palette)
    fbo_particles.bind()         → instanced quads, ~400 in drilling / ~80 in library
    fbo_ui.bind()                → pyglet 2D batch (cards, text, widgets)
    fbo_post.bind()              → bloom (downsample → blur → add) + vignette
    blit fbo_post → screen
```

### 5.2 AppState

```python
@dataclass(slots=True)
class AppState:
    mood: float            # 0..1, lerped toward mood_target each frame at k=1.8/sec
    mood_target: float
    streak: int
    accuracy_window: deque[bool]   # last 10 answers
    current_view: str
    intensity: float       # 0..1, multiplier for bloom + particle count + aurora amplitude
    mode: Literal["drilling", "library"]
```

### 5.3 Event → mood-target deltas

| Event | Δ mood_target | Particle effect | Bloom effect |
|---|---|---|---|
| Correct answer | +0.10 | Small radial burst at card center | None |
| Streak hits 5 | +0.30 | Wide spiral | Brief bloom up |
| Streak hits 10 | +0.50 (cap 1.0) | Screen-wide bloom | Sustained 2 s |
| Wrong answer | −0.15 | Particles scatter outward, then return | Dim flash |
| Idle 30 s | drift to 0.5 | Particles slow | Ambient |
| View change | mode-pack swap | None | 600 ms tween |

Mood lerps toward target at **k = 1.8 / sec** — fast enough to feel reactive, slow enough to avoid twitch.

### 5.4 Mode packs

Mode is not two pipelines — it's two preset uniform packs sharing one pipeline:

```python
MODE_DRILLING = ModePack(intensity=1.00, particles=400, bloom=0.60, card_tilt=0.18)
MODE_LIBRARY  = ModePack(intensity=0.40, particles= 80, bloom=0.15, card_tilt=0.00)
```

On view transition between drilling-class views and library-class views, all mode-pack uniforms tween over **600 ms**. No snap. The world stays continuous — walking from a loud room into a library, not slamming a door.

### 5.5 Shader uniforms by pass

- **Aurora**: `(u_time, u_mood, u_intensity, u_palette_a, u_palette_b)` — `palette_a/b` are Navy-cool and goldenrod-warm endpoints; final color is `mix(a, b, mood)`
- **Particles**: `(u_time, u_target_count, u_color, u_burst_origin, u_burst_age)` — burst events push radial impulses
- **Card**: `(u_time, u_tilt, u_seed)` — generative per-card decoration; `seed` derived from card id for stable look
- **Post**: `(u_bloom_strength, u_vignette)` — both scale with `intensity`

## 6. Data Flow & Persistence

### 6.1 Read path

```
data/bibs/<BIB>/questions.json   →  bibs.load_bib() →  in-memory cards list
data/bibs/<BIB>/study-guides/*.md →  markdown_render.parse() →  AST per doc (lazy, cached)
db.read_state(bib_id)             →  SRS state for current Bib
srs.next_due(cards, state)        →  next card the SRS wants to show
```

### 6.2 Write path

```
user grades card  →  srs.update(card, quality)  →  new EF + interval + due
                  →  db.write_state(bib_id, q_id, ...)
                  →  AppState event Δ (correct / wrong / streak)
                  →  shader uniforms next frame
```

### 6.3 SQLite schema (`~/.bibmaxxing/state.db`)

```sql
CREATE TABLE srs_state (
  bib_id      TEXT NOT NULL,
  question_id TEXT NOT NULL,
  ef          REAL NOT NULL,    -- SM-2 ease factor
  interval    INTEGER NOT NULL, -- days
  reps        INTEGER NOT NULL,
  due         INTEGER NOT NULL, -- unix ms
  last_q      INTEGER,          -- 0..5 quality
  last_at     INTEGER,
  PRIMARY KEY (bib_id, question_id)
);
CREATE INDEX idx_due ON srs_state (bib_id, due);

CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT
);

CREATE TABLE history (
  id      INTEGER PRIMARY KEY,
  bib_id  TEXT NOT NULL,
  ts      INTEGER NOT NULL,
  event   TEXT NOT NULL,        -- 'answer', 'view_change', 'session_start', ...
  payload TEXT                  -- JSON blob
);
CREATE INDEX idx_hist_bib_ts ON history (bib_id, ts);
```

Per-Bib scoping is via the `bib_id` column on every row, mirroring the web app's per-Bib design.

### 6.4 Import/export bridge with the web app

- `bibmaxxing import <state.json>` — reads the web app's export shape, populates SQLite.
- `bibmaxxing export <out.json>` — writes the same shape back.
- You can grind in either app, dump, and merge. Same `data/bibs/` directory — content shared.

### 6.5 Dev-mode file watcher (off in release)

- Watches `data/bibs/<BIB>/study-guides/*.md` and `src/bibmaxxing/render/shaders/*.glsl`.
- Touch a file → reload AST or recompile shader live, no relaunch.
- Powered by `watchdog`.

## 7. Widget Toolkit

The widget layer is the largest single chunk of the project — most of the LoC, all built once.

| Widget | Responsibility | LoC budget |
|---|---|---|
| `FocusManager` | Tab order, keyboard focus, focus-ring rendering, Esc/Enter/arrow semantics | ~120 |
| `Button` | Hover/focus/press states, click + keyboard activation, label + icon | ~150 |
| `TextInput` | Single + multiline, IME-friendly, selection, paste, basic undo | ~300 |
| `ScrollView` | Vertical scroll with momentum, scrollbar, overscroll, child layout | ~250 |
| `Modal` | Overlay, focus trap, dismiss-on-Esc, dim background | ~100 |
| `MarkdownView` | Token tree → primitive layout → scroll-view-rendered (see §8) | ~600–900 |
| **Total** | | **~1500–1820** |

### 7.1 Shared idioms

- Each widget owns its hit-rect and a dirty flag; redraws only on state change.
- All widgets read from `theme.py` (Navy + goldenrod, dark + light variants).
- Rendering uses `pyglet.shapes.Rectangle/RoundedRectangle` + `pyglet.text.Label/TextLayout`.
- "Fancy" decorations (focus-ring glow, hover lift) are a small ModernGL post-effect on the focused widget's bounding box, **not** a per-widget shader.

### 7.2 Keybinding map

| Key | Action |
|---|---|
| `Space` / `Enter` | Reveal answer / activate focused button |
| `1`..`5` | Grade card (Again / Hard / Good / Easy / Perfect) |
| `J` / `K` or `↑` / `↓` | Navigate cards / list items |
| `g` then `f` / `q` / `e` / `s` | Vim-style leader: jump to flashcards / quiz / exam / study-guides |
| `Tab` / `Shift-Tab` | Cycle widget focus |
| `Esc` | Close modal / cancel input / back |
| `?` | Show keybindings overlay |
| `/` | Search (in study guides) |
| `n` / `N` | Next / previous search match |
| `o` | Toggle TOC sidebar (in study guides) |

### 7.3 Keybinding discoverability (no shortcut is invisible)

Three layers, all reading from a single `KEYBINDINGS` table in `keybindings.py`:

1. **Always-visible status bar** — bottom of the window, ~24 px, context-sensitive:
   - Drilling, card revealed: `1 Again · 2 Hard · 3 Good · 4 Easy · 5 Perfect · ? Help`
   - Drilling, card hidden: `Space Reveal · N Skip · ? Help`
   - Library: `↑↓ Scroll · / Search · Esc Back · ? Help`
   - Dashboard: `g f/q/e/s — jump · ? Help`
2. **Inline labels** — small dim glyphs next to interactive elements (`[1]`..`[5]` superscripts on grade buttons, `[Space]` next to "Reveal").
3. **`?` overlay** — translucent panel grouping all bindings by context (Global / Drilling / Library / Add / References). Aurora keeps drifting behind. Esc dismisses. Pops once on first launch with a "press ? anytime" hint.

## 8. Markdown Rendering (Library Mode)

### 8.1 Pipeline

```
file.md
  → markdown-it-py.parse()        → flat token stream
  → MarkdownView.build_tree()     → tree of primitive layout nodes
  → MarkdownView.layout(width)    → list of (y_offset, primitive) tuples
  → ScrollView renders            → translate y on scroll, no re-layout
```

Layout runs on **width change only** (resize, sidebar toggle). Scrolling is a y-translate over pre-laid-out primitives — performance is fine.

### 8.2 Primitive layout nodes

| Node | Renders as | Concerns |
|---|---|---|
| `Paragraph` | `pyglet.text.layout.IncrementalTextLayout`, multi-line wrap | Inline bold/italic/code via styled-text |
| `Heading` H1–H6 | Larger label, optional underline rule | Anchor IDs preserved for in-doc links |
| `List` (ordered/unordered) | Indented paragraphs with bullet/number gutter | Nested lists indent further |
| `CodeBlock` (fenced) | Fixed-width font, slight darker bg, syntax-highlighted via `pygments` | Horizontal scroll for long lines |
| `Table` | Column-width measure pass + grid layout | Hardest single node (~150–250 LoC) |
| `Image` | `pyglet.image.load`, scaled to text-column width | Texture cache so re-scrolling doesn't reload |
| `HorizontalRule` | Thin shape | Trivial |
| `Blockquote` | Indented + accent-colored vertical bar in gutter | Trivial |
| `InlineLink` | Color-shifted span; opens default browser on click/Enter | Cross-doc links resolved relative |

### 8.3 Search & TOC

- `/` opens an inline search field; matches highlight in place; `n`/`N` cycle.
- `o` toggles a TOC sidebar built from H1/H2/H3 of the current doc.

## 9. Error Handling

Policy: **degrade, don't crash.**

| Failure | Behavior |
|---|---|
| Missing image asset | Render `[image: filename]` placeholder, log WARNING |
| Corrupt SQLite | On open: integrity check fails → rename to `state.db.broken-<ts>`, start fresh, attempt restore from last auto-export |
| Shader compile error | Fall back to flat-color shader, dev-mode toast with error, log ERROR |
| Markdown parse failure | Render file as plain text with "couldn't parse" banner, log WARNING |
| Unknown question schema fields | Ignore them; never let bad data brick the app |
| Uncaught exception | `CRITICAL` handler writes `crash-<ts>.json` next to log + traceback, exits cleanly |

## 10. Logging

### 10.1 Stack

Stdlib `logging` + `RotatingFileHandler`. No extra deps.

### 10.2 Files

```
~/.bibmaxxing/
  log.txt          ← active log
  log.txt.1        ← previous rotation
  log.txt.2..5     ← older (5 max kept; ~50 MB ceiling, oldest auto-deleted)
```

Each file caps at **10 MB** then rotates.

### 10.3 Levels

| Level | Content | When emitted |
|---|---|---|
| DEBUG | Every state transition, key press, SRS calc, uniform write, asset cache hit/miss | Only with `--verbose` or `BIBMAXXING_LOG=DEBUG` |
| INFO | View changes, Bib switches, card answered (q+EF+interval), session start/stop | Default |
| WARNING | Missing asset, corrupt cache, shader fallback, slow frame >33 ms | Always |
| ERROR | Caught exception, DB integrity fail, MD parse fail | Always — full traceback |
| CRITICAL | Uncaught exception | Always — traceback + state dump to `crash-<ts>.json` |

### 10.4 Format

```
2026-04-29 14:32:18.473 [INFO ] srs        bib=CWT-E7 q=cwt-e7-jp312-c1-001 quality=4 ef=2.45 interval=8d
2026-04-29 14:32:18.475 [DEBUG] state      mood 0.62 → 0.72 target (correct +0.10)
2026-04-29 14:32:18.476 [DEBUG] aurora     uniform u_intensity 0.78 → 0.84
```

Single line per event, structured K=V tail — greppable, awk-friendly.

### 10.5 Configuration

- CLI: `--verbose` (DEBUG), `--quiet` (WARNING), `--log-level=INFO`, `--log-file=path`
- Env: `BIBMAXXING_LOG=DEBUG`
- In-app: Settings view exposes log level + "Open log folder" button

### 10.6 Verbose-mode coverage

- **State**: every mood lerp tick crossing a 0.05 threshold, every view change, every mode-pack swap
- **SRS**: card pulled from queue, EF inputs/outputs, due-date math, queue size after update
- **DB**: every write (with row count), every read >5 ms, integrity-check result on open
- **Render**: shader compile log on first load, FBO resize, frame time when >33 ms
- **Asset**: image load (path, size, ms), cache hit/miss, font load, audio load
- **Input**: every key press in DEBUG mode (so a session can be replayed from log)
- **Markdown**: per-doc parse time, primitive count, image count, table count

### 10.7 What logging is NOT

- Not analytics. Stays local. Never phones home. No telemetry.
- Not a state store. SRS state lives in SQLite; logs are append-only audit history.

### 10.8 Crash dump

On uncaught exception, the CRITICAL handler writes `~/.bibmaxxing/crash-<ts>.json`:

```json
{
  "ts": 1714409538473,
  "version": "0.1.0",
  "view": "flashcards",
  "current_bib": "CWT-E7",
  "last_question": "cwt-e7-jp312-c1-001",
  "app_state": {"mood": 0.72, "streak": 4, "intensity": 0.84},
  "exception": {"type": "...", "message": "...", "traceback": "..."}
}
```

One file per crash. Enough to reproduce in a future session.

## 11. Testing

### 11.1 Unit (pytest)

- `test_srs.py` — port the SM-2 cases from the JS test suite; verify EF/interval math.
- `test_db.py` — round-trip writes; integrity-check failure path; per-Bib scoping.
- `test_markdown_render.py` — token stream → primitive list, including tables, code blocks, inline images.
- `test_state.py` — mood lerp converges at expected k; event Δs; mode-pack tweens.

Target: **~70%** coverage on logic modules. Render code is tested via golden images, not unit.

### 11.2 Headless integration

- `--headless` flag skips window/render, exercises full state machine for CI.
- One end-to-end script: load Bib → answer 50 cards → assert SRS state matches expected.

### 11.3 Golden-image visual regression

- `--screenshot <view>` flag captures one frame to PNG.
- Reference PNGs in `tests/golden/`. Pixel diff in CI catches visual regressions.
- Tolerant comparison (e.g., 0.5% pixel difference threshold) since shaders have minor floating-point noise.

## 13. Migration Story

1. **Web app stays as-is.** Both apps coexist, point at the same `data/bibs/`.
2. **First run** of `bibmaxxing-py`:
   - Creates `~/.bibmaxxing/`
   - Initializes empty SQLite
   - Prompts: "Found existing Bibmaxxing web app data. Import? [Y/n]"
3. **On Yes**, opens a file dialog → user selects the web app's exported JSON → SQLite populated.
4. **Going back to the web app** — `bibmaxxing export out.json` → import in the web app's Settings page.
5. Bidirectional. No lock-in either direction.

## Appendix A — Decision Log

| Decision | Choice | Why |
|---|---|---|
| Motivation tier | A — daily driver | Shapes ergonomics over showcase |
| Visual ambition | C — maximalist | Drives shader-capable stack |
| Art source | A — pure procedural | No asset wrangling; minimal-setup ethos |
| Mascot | D — no mascot, ambient-only | Avoids character-design rabbit hole; cleaner aesthetic |
| Study-guide rendering | B — two-zone (drilling + library) | Tier-C identity for workout, calm for reading |
| Framework | Approach 1 — Pyglet + ModernGL | Maximum shader ceiling + best library-mode text layout |
| Persistence | SQLite | Natural Python equivalent of IndexedDB |
| Logging | Stdlib + RotatingFileHandler, K=V tail format | Verbose by flag, structured for grep |
| Distribution | PyInstaller single-file `.exe` | Boat-workstation deployable, no admin needed |
